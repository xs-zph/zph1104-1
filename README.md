# AI 客服工单自动化系统

一个基于大模型的电商客服系统：以**聊天式 AI 客服**的形式接待客户，**像真人一样寒暄**，同时能**调用工具查询订单/物流/退款等真实数据**，并**结合 RAG 知识库**精准回答常见问题；处理不了的问题自动转人工客服跟进。

> 技术栈：Python + FastAPI + DeepSeek API（Agent 工具调用）+ MySQL + ChromaDB（RAG）

## ✨ 功能特性

- **登录鉴权**：账号密码登录 + Bearer Token 会话，区分「客户」和「客服」两种角色
- **聊天式 AI 客服**：能自然寒暄、自我介绍（"你好"→ 自我介绍），不是冷冰冰的工单处理器
- **Agent 工具调用**：AI 客服能调用工具查询订单状态、物流进度、退款进度，回答基于真实数据，不靠编造
- **订单归属校验**：订单/物流/退款查询自动绑定当前登录用户，只返回本人数据，防止越权查到他人订单
- **RAG 知识库**：将 FAQ/产品手册向量化存入 ChromaDB，语义检索 + 精准回答，覆盖 80% 常见问题
- **文档切块向量化**：产品手册/政策文档按段落切块（带重叠）后向量化，支持语义相似度检索
- **知识库实时更新**：后台新增 FAQ 立即写入向量库并生效，无需重启
- **人工回答回流知识库**：转人工的问题，客服回答满意后一键存入知识库，AI 下次同类问题直接自动回答（系统越用越聪明）
- **7 类工单自动分类**：物流查询、退货申请、商品咨询、售后维修、发票问题、退款纠纷、人工处理工单（Few-shot + CoT）
- **条件路由**：根据「分类 + 置信度」决定自动处理还是转人工——**人工是最后保证**，普通问题尽量自动回答
- **人工升级闭环**：转人工的工单进入客服后台，客服可标记「已处理」
- **微信公众号接入**：预留 `/wechat` 接口，微信用户可直接和 AI 客服对话
- **效果可量化**：自动处理率、分类准确率、平均耗时、类别分布、满意度一目了然
- **多轮对话记忆**：按用户缓存近期对话历史，客户追问（"那第二单物流呢"）能结合上下文理解，无需重复描述
- **满意度评价闭环**：每条自动业务回复附带 👍👎 评价按钮，满意度沉淀到指标面板，形成「回答 → 评价 → 优化」闭环
- **快捷引导菜单**：侧边栏内置高频问题，一键提问，降低客户输入门槛
- **用户自助服务**：客户可在线「查我的工单进度」「取消待发货订单」，无需转人工
- **隐私边界三层防护**：手机号/身份证/银行卡/邮箱脱敏后才进 LLM、数据库和日志，从源头杜绝隐私泄露
- **情绪安抚**：客户表达不满/生气/焦虑时，AI 先共情安抚再解决问题，不让客户被冷冰冰对待
- **日常问答（Agent 工具）**：问「几点了」「天气怎么样」由 DeepSeek 调用 get_time / get_weather 工具拿到真实时间/天气，再组织成自然回答
- **响应缓存提速**：重复问题命中内存缓存直接返回，跳过分类 + 大模型，二次回答近乎零延迟
- **上下文护栏**：超长输入自动截断、输出 token 上限控制，避免触发模型上下文窗口溢出
- **日志系统**：运行日志写入 `logs/` 文件夹（不记录用户隐私）

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 配置环境变量

```bash
copy .env.example .env    # Windows
cp .env.example .env      # Linux / macOS
```

编辑 `.env`，填入 DeepSeek 密钥和 MySQL 连接信息：

```ini
DEEPSEEK_API_KEY=sk-你的密钥
DEEPSEEK_MODEL=deepseek-chat

MYSQL_HOST=localhost
MYSQL_PORT=3308
MYSQL_USER=root
MYSQL_PASSWORD=你的数据库密码
MYSQL_DB=ai_ticket

CONFIDENCE_THRESHOLD=0.8

# 微信公众号（可选）
WECHAT_TOKEN=ai_ticket_wechat_token
```

> 密钥申请：https://platform.deepseek.com
> 数据库由程序自动创建（`ai_ticket` 库 + `tickets`/`users` 表）。

### 3. 初始化知识库（RAG）

```bash
python scripts/seed_faq.py        # FAQ 问答对 → 向量库
python scripts/demo_rag.py        # 产品文档切块 → 向量化 → 相似度检索演示
```

> 默认用中文语义模型 `BAAI/bge-small-zh-v1.5` 向量化（首次自动下载，走 hf-mirror 镜像）；离线时自动回退本地哈希。

### 4. 启动系统

```bash
python run.py
```

访问 **http://127.0.0.1:8000**，自动跳转登录页。

     ```
     "C:\Users\pc\cpolar\cpolar\cpolar.exe" authtoken 你的TOKEN
     ```

2. 之后双击 `start_cpolar.bat`（或在项目目录运行 `start_cpolar.bat`）即可。

> cpolar 免费版会分配一个固定的 `xxx.cpolar.cn` 域名，重启后不变，适合答辩。

## 🧠 设计说明（答辩重点）

- **Agent 与 RAG 结合**：不是"只靠 RAG 背 FAQ"，而是让大模型**自行决定调用哪个工具**——查知识库（RAG）、查订单、查物流、查退款，最后汇总成自然回复。知识库查不到时如实告知，绝不编造。
- **人工是最后保证**：普通咨询尽量自动回答，只有资金纠纷、大额赔付、法律、强烈投诉情绪才转人工，体现「AI 兜底 + 人工把关」。
- **知识库实时更新**：新增 FAQ 直接写入向量库并持久化，无需重启即可被检索，支撑知识库持续扩充。
- **为什么用 MySQL**：工单系统需要持久化、多用户并发，MySQL 更适合生产环境。
- **真正的语义检索**：默认用中文语义模型 `BAAI/bge-small-zh-v1.5`，把「字面不同但语义相同」的问题映射到相近向量（如「手机没到」→「物流查询」「这个能退吗」→「退货政策」）；模型不可用时自动回退本地哈希，保证离线可用。
- **文档切块**：产品手册/政策文档（`data/docs/`）按段落切块、带重叠，向量化后存入 ChromaDB 的 `docs` 集合，用 `retrieve_docs()` 做相似度检索，与 FAQ 问答对检索互补。
- **订单归属**：订单存在 MySQL 的 `orders` 表并绑定 `username`；Agent 查订单/物流/退款时由服务端注入登录身份，SQL 强制 `WHERE order_id=? AND username=?`——模型只能决定「查哪个订单号」，无法越权查询他人订单。
- **阈值怎么定的**：分类置信度阈值不是拍脑袋，而是在带真实标签的评测集上做「阈值扫描」（`scripts/tune_threshold.py`），在误转人工 / 漏转人工之间取总错误率最低的值（实测 0.8 最优，能兜住「分错且低置信」的难样本）。
- **隐私边界**：手机号/身份证/银行卡/邮箱用正则脱敏（`app/privacy.py`）后才进 LLM、落库、写日志——三层一致脱敏；提示词同时约束 AI 不主动索要敏感信息，业务办理只需订单号。
- **上下文窗口管理**：DeepSeek 上下文窗口约 128K token，正常业务远够用；为防「超长输入/超长检索结果」顶满窗口，输入侧截断到 4000 字符、Agent 输出 token 上限 1024，保证永不溢出、永不截断。
- **多轮记忆**：按用户名维护一个固定长度的消息队列（`app/memory.py`），把近期对话注入模型上下文，客户省略主语追问也能对上号；「新对话」一键清空。
- **满意度闭环**：客户点 👍👎 → `POST /api/tickets/{id}/feedback` 落库 → 后台指标面板展示满意度率，评价数据反哺运营。
- **情绪安抚**：在分类 / Agent / 闲聊三层提示词里都要求「先共情安抚、再解决问题」，负面情绪优先照顾感受，其次才是效率。
- **日常问答（Agent 工具）**：DeepSeek 没有实时时钟、也不联网，直接问它「现在几点了」会编造答案；所以时间读服务器时钟、天气调 wttr.in（免费无 key，5 分钟缓存 + 2.5 秒超时降级），由 Agent 调用 get_time / get_weather 工具拿到真实数据后再组织回答——**实时信息靠工具、语言表达靠大模型**。
- **响应缓存**：`app/cache.py` 用 LRU 缓存确定性回复（闲聊/模板），重复问题直接命中，跳过「分类 + 大模型」两步，实测二次回答耗时从秒级降到毫秒级；订单/物流/天气等会变化的结果刻意不缓存，避免返回过期数据。
- **速度三件套**：① 输入截断（超长问题不拖慢）② 输出 token 上限（回复不啰嗦）③ 响应缓存（重复问题跳过「分类 + 大模型」，能不走就不走）。
